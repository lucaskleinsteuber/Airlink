# AirLink 0.4 — optional incoming-file organization (protocol 1)

Version 0.4.0. Existing transfers, shares, relay and clipboard remain compatible. New organization capabilities apply to files received by a desktop service, not browser-managed downloads or relay payloads. No source files, existing received files or share originals are automatically moved, deleted or overwritten.

## Settings and paths

Settings adds `organization:{detectDuplicates:false,sortEnabled:false,rules:[]}`. Both features are opt-in for new and migrated installations. UI may offer editable Images/Videos/Audio/Documents/Archives presets before enabling; backend never silently enables or invents sorting. Rules are ordered `{id,extensions:["jpg","png"],folder:"Images"}`, extension case-insensitive with optional leading dot normalized. First matching rule wins. Folder is a safe relative directory, never absolute, traversal, symlink or .airlink-partials. Reject conflicting/case-colliding destinations before receive; never overwrite.

Only top-level individual files are classified by extension; transferred folders and all their hierarchy stay together unchanged. Rules snapshot at incoming offer creation, so changing settings never moves active/completed data or changes resume paths. File.path remains the immutable original wire path. New File.destinationPath is the snapshotted relative host path inside its unique transfer receive directory; root filesystem operations must consistently use it. Private admin/native status can show it; guest DTOs and peers omit it. Shares created from organized received transfers use the actual destination mapping without leaking host paths. Historical transfers without destinationPath use original path.

## Content-based duplicate decision

Use SHA-256 plus size and full streaming revalidation of the indexed existing candidate before offering Skip; filename alone never matches. Only AirLink-managed verified received files are indexed, including import from existing completed incoming history. The index persists independently of history clear. No scan of arbitrary user libraries; no whole-file RAM load/copy. Missing, modified or replaced candidates are invalidated. Recheck the chosen existing file at Skip, so stale offers cannot silently discard an incoming file. At most one verified matching candidate is enough for the first version.

- `POST /api/v1/transfers/{id}/files/{fileId}/prepare` `{sha256}` -> `{decision:"upload"|"pending"|"skip",transfer:Transfer}`. Authenticated owning sender only, after regular recipient approval. Updated senders call this after their existing full source hash and before first bytes. Disabled detection returns upload. Public response never exposes candidate IDs/paths or host destination mappings.
- Local IPC `duplicate.resolve {transferId,fileId,action:"keep"|"skip",candidateId?}` -> Transfer. Only host administration resolves. Keep receives a separate new copy in the planned unique destination; Skip requires a revalidated matching candidate and marks skipped/completed without copying the existing file. Never create a placeholder pretending payload exists. Existing directory entries may remain as structure.
- Local IPC `duplicate.path {candidateId}` -> `{path}`. Native Show explicitly reveals the existing file; portable console shows/copies the path after a user action. This command is never exposed through the guest API.

New states `checkingDuplicate` and `waitingDuplicate`. Checking performs streaming candidate validation outside the global engine lock, cancellable and generation guarded like verification. A waiting decision releases receive scheduling capacity. Source UI shows host attention required; source cannot resolve itself. SSE checkingDuplicate must not abort the active prepare/hash request. Keep/Skip requeues or completes correctly; paused/cancelled work must never be revived by a stale decision/hash result.

New file fields: skipped, duplicateState (empty/checked/pending/keep/skipped), duplicateCandidates (private host only), destinationPath (private host only). Transfer.skippedBytes is bytes avoided, `size-received` for skipped files. CompletedBytes remains actually confirmed data, including bytes already received before a legacy-client duplicate is discovered. Progress uses completedBytes+skippedBytes. Statistics adds skippedFiles/skippedBytes, separate from confirmed and lifetime traffic; do not inflate network totals.

Legacy senders may omit prepare. While a host decision is pending, the complete endpoint returns HTTP 409 rather than a premature success; old senders keep polling. Keep publishes already-verified staging in the background even if the source has disconnected. Private IPC accepts out-of-order replies for duplicate.resolve, with at most two checks and no fixed client hash timeout; status/pause/cancel remain responsive. Full-file verification still runs at complete; enabled detection can pause before publishing a verified staging file for the same explicit host Keep/Skip choice. Removing this transfer's private staging file after explicit Skip is allowed; existing indexed/original files are never removed. New source senders propagate skipped state/progress without marking missing source payload as a received file. Normal engine download/range/export APIs must not open skipped non-existent files.

## Tests and delivery

Background tests only, no UI automation or /Applications installation. Verify equal-name/different-content vs different-name/equal-content, stale/deleted/symlink candidates, cancellation/restart/duplicate request epochs, mixed skipped/sent progress, index after history clear, sorted-path collision/traversal, folder preservation, immutable settings snapshots, legacy complete path and source skip propagation. New private preview DMG and portable archives follow the existing version/signing/release policy.
